Root cause repaired:
- 16.0.157 Schedule Builder browser React code directly imported ../core/scheduleWarningControls.cjs and normalized CommonJS/default exports before destructuring render-time helper functions.
- The ScheduleCopilot render path calls buildCoverageVarianceRows() and buildScheduleConflictWarningRows() immediately when Schedule Builder renders.
- In the production browser bundle, a CommonJS/browser interop mismatch can leave those bindings non-callable, producing a TypeError before the Warnings panel is opened.

Exact repair:
- Removed the direct .cjs dependency from src/features/schedule.jsx.
- Added src/core/scheduleWarningControls.shared.js as the single shared implementation.
- Added src/core/scheduleWarningControls.js as the browser-native ESM named-export wrapper.
- Replaced Schedule Builder imports with explicit named imports from ../core/scheduleWarningControls.
- Kept src/core/scheduleWarningControls.cjs as a tiny Node/CommonJS wrapper over the same shared implementation so existing Node tests can keep requiring it.

Important preserved behavior:
- ScheduleCopilot remains enabled.
- Under-coverage warnings remain.
- Over-coverage warnings remain.
- Requested-off employee-name warnings remain.
- Warning dismissal remains.
- Request Off filter/bulk behavior remains.
- AppSurfaceErrorBoundary and /api/report-bug remain active.
- No blanket try/catch or crash swallowing was added.
