# 16.0.232 copy and clarity map

This release reviews active customer-facing screens without changing their behavior, navigation, permissions, or data model. The table records the largest wording changes; small error, empty-state, and button-label edits follow the same approach.

| Area | Old wording | New wording | Why |
| --- | --- | --- | --- |
| Inventory navigation | AI Order Assistant | Order Suggestions | Describes the manager task without overstating automation. |
| Inventory forecast | Python Intelligence Layer / Run Python Forecast | Advanced Order Forecast / Run Order Forecast | Explains the outcome instead of the implementation technology. |
| Inventory action | Apply Selected to Draft | Add Selected to Order Draft | Makes the button's result explicit and confirms it is still a draft. |
| Inventory empty state | No order pressure detected | Nothing needs ordering right now | Uses normal restaurant language and does not make a healthy state sound like an error. |
| Manager Brief | Python Ops Scan | Restaurant Check | Describes what the manager is asking the app to review. |
| Manager Brief status | Needs Eyes | Need Review | States plainly that a manager should review the item. |
| Schedule tools | Schedule Copilot / Smart Fill | Schedule Tools / Fill Coverage Gaps | Names the job being done and keeps the result clearly reviewable. |
| Schedule action | Submit / generic Error | Send Request for Review / task-specific message | Tells employees what happens next and gives useful recovery guidance. |
| Authentication | Save & Enter OS | Save Password & Sign In | Uses a familiar, accurate sign-in action. |
| App update recovery | Stale chunk / runtime recovery | App update available / Refresh App | Removes developer terminology from an employee-facing recovery screen. |
| Menu impact | Dependency Radar / precision graph | Menu Items Affected / inventory and prep check | Explains the operational result before technical matching evidence. |
| Scanning hub | AI Tools | Kitchen Tools | Groups the available work without repeatedly advertising AI. |
| Back Office | Python Alert Follow-up | Restaurant Check Follow-up | Gives owners a useful approval category in everyday language. |
| Schedule audit | Classification-only technical text | Plain-English result first, technical evidence second | Lets System Administrators understand the consequence while preserving troubleshooting evidence. |

Historical release-note entries and deliberately hidden legacy components remain unchanged where they document the wording or behavior of an older release. System Administrator evidence retains technical terms when those terms are necessary for troubleshooting.
