## 3. Credential-rotation race repair

The signed assertion now carries `credentialVersion`. Verification captures that exact version, `kid`, and a canonical SHA-256 fingerprint of the ES256 public key material. Inside the replay/quota transaction the installation is reread and issuance requires the version, active key, and fingerprint to remain identical. Different-`kid` rotation and same-`kid`/new-key replacement both fail before replay evidence is consumed. Assertion time validity is rechecked inside the transaction so a delayed transaction cannot mint from an expired assertion.

## 4. Human control-plane authority repair

Bridge administration now performs revoked-token checking, Firebase Auth-user lookup/disabled checking, active account checking, active canonical `workspaceMembers` checking, exact OWNER/ADMIN checking, canonical restaurant activity checking, App Check, MFA through the existing authorization path, and recent-auth checks. A missing or inactive canonical membership wins over all legacy workspace fields. Manager and team/settings-permission-only identities remain denied.

## 5. Mapping lifecycle repair

Mapping creation produces revision 1 and an exact retry while approved is a zero-write/idempotent result. Revocation requires `expectedRevision` equal to the current approved revision. Revoked mappings cannot be recreated by `create`; no implicit reapprove action exists. Stale revisions conflict. Employee targets are rejected when disabled, deleted, archived, removed, revoked, inactive, or foreign-tenant. Firestore transactions preserve final revocation under concurrent stale create/revoke attempts.

## 6. Sequence checkpoint repair

Sequence advancement remains capped at 256 slots per transaction. Stream evidence now distinguishes `checkpointWorkPending` from actual missing sequences. Reconciliation performs one bounded continuation transaction per call, allowing an idle stream to converge through repeated reconciliation without unrelated events. Exact 256-slot boundaries finish immediately; multiple windows converge; `missingSequenceCount` remains based on actual absent transport evidence; checkpoint-only work reports `checkpoint-pending`, not `transport-gaps`.

## 7. Partial-batch response contract

Event batches still commit one event at a time. A fully successful batch returns HTTP 200. A stopped batch returns HTTP 207 with ordered per-event results. Outcomes are `accepted`, `duplicate`, `conflict`, `rejected`, `retryable`, or `unattempted`. Previously committed receipts are returned; the failed index is explicit; later entries identify the blocking index. Retryable failures include `commitState: "unknown"`. Whole-batch and partial retries remain idempotent, and persistent conflicts remain visible instead of hiding later entries.

## 8. Reconciliation evidence changes

`duplicateDeliveryAttempts` was removed because exact retries intentionally perform zero writes. `semanticRejectedEvents` and event-level rejected manifest claims were removed. Schema failures record only the aggregate `validationFailureAttempts` counter and never store the rejected payload. Manifest comparison now returns only `present`, `missing`, or `conflicting`; malformed manifest entries reject the request.

## 9. Simulator safety repair

Simulator execution requires an unambiguous `demo-*` or `chaos-test-d1601` project, an HTTP loopback base URL, and a loopback Firestore emulator host with a port. Hostnames must resolve exclusively to loopback addresses. Production `cheers-34b8d`, production mode, missing settings, conflicting project variables, remote emulator hosts, and arbitrary database objects without validated target proof are rejected before database access. Emulator-test cleanup uses the same validation. The simulator now uses the real installation services, performs a real foreign-installation rejection, reloads the storage module for restart replay, and verifies durable receipt state.

## 10. Tenant deactivation behavior

Every current machine-authority check reads the canonical `restaurants/{restaurantId}` document. A missing, inactive, disabled, deleted, archived, removed, revoked, or deactivated restaurant disables token use and event acceptance immediately. Registration and lifecycle transitions also check the same canonical tenant state.

## 11. Suspend/resume behavior

Suspension transactionally increments `credentialVersion`. Old access tokens remain stale after resumption and can never revive. A new assertion carrying the new credential generation is required after resume; the existing key may be reused only through fresh authentication.

## 12. Semantic validation changes

Business dates must be real calendar dates. `occurredAt`, `openedAt`, and `closedAt` must be real UTC timestamps; `closedAt` cannot precede `openedAt`; and `occurredAt` more than five minutes in the future is rejected. Money remains integer cents. The response explicitly states `financialReconciliation: "not-performed"`; schema-valid staged evidence is not represented as accounting-verified.
